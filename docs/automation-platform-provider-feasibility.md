## Minimum real-provider acceptance contract

Qualification is a reviewed decision for **one field, provider/recipe revision, exact game build and declared operating conditions**. A provider cannot declare itself qualified, and a JSON receipt cannot independently establish its own truth.

| Gate | Required evidence |
| --- | --- |
| Identity/build | Explicit process binding, PID plus creation identity/handle lifetime, image/module evidence, exact executable/recipe revision. Distinguish an on-disk file hash from proof of the mapped image. Unknown/changed identity invalidates support. |
| Semantics | Meaning, units/axes/frame, value/missingness rules and tolerance, independent reference and changed-state agreement. Native candidates must reject stale copies and reacquire across full process restart. |
| Acquisition timing | Host monotonic start/end/receive/apply times with ordered bounds. Native read recency without a producer timestamp is not producer age. UTC is diagnostic only. |
| Source liveness | Explicit producer-clock/sequence/heartbeat availability, reset behavior and cross-clock uncertainty. Equal stationary values can be fresh; redelivery of the same retained frame cannot refresh production time. |
| Lifecycle | Separate process/session, reader binding and producer boot/source/stream epochs. Reload, restart, zone/character changes and old callbacks invalidate the appropriate scope; sequence alone is not global identity. |
| Faults/continuity | Missing, invalid, error, stale, duplicate/reordered/conflicting frames, partial/torn/unreadable reads, gap/resync, disconnect/reconnect and late results. Snapshot freshness does not establish event continuity. |
| Quality budget | Predeclare limits for the specific consuming capability, then record samples, duration, conditions, latency/source-age where measurable, worst outages, errors/gaps and CPU/allocation/handle cost. Include failed windows and unavailable time. |
| Conclusion | Untested, failed, observed-but-unqualified or qualified for a stated scope. A diagnostic-only result must not enable gameplay decisions. Preserve exact source/package/observed-active identity. |

Lua-specific requirements:

- Continuous telemetry, if selected, must be a separate opt-in/versioned addon; retain manual collector behavior and frozen RAC formats.
- A valid frame is not proof that every field is current or sampled atomically. Validate player binding around acquisition and per-field availability.
- Clock loss/regression, reload, counter exhaustion and serialization failure require explicit unavailable/fenced recovery behavior.
- Lua globals are in-process publication, not desktop IPC. Do not assume sockets, arbitrary files, immediate SavedVariables updates or game messaging provide Windows transport.
- A checksum/content hash identifies/checks bytes; it does not prove freshness, identity or a live producer.
- Capture/decoder tests with synthetic data or a retained frame are not sustained live transport qualification.
